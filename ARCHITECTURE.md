# AI-сервис POST /triage - архитектура и критерии «готово»

Шаг 1 из 7 (Практика 2, 08.10.2026, срок 14 дней). Документ рабочий: правится по ходу, итог уйдёт в отчёт.

## 1. Задача одной фразой

Сервис принимает обращение клиента, определяет категорию, пишет черновик ответа и решает, нужен ли человек. Каждое обращение и результат пишутся в базу.

Управленческая аналогия: это первая линия поддержки. Она раскладывает входящие по папкам, отвечает на типовое и сразу зовёт руководителя, если дело сложное или она сама не уверена.

## 2. Контракт (как в задании, не меняем)

**Запрос** `POST /triage`

| Поле | Тип | Правило |
|---|---|---|
| `text` | строка | 1-2000 символов, не пустая после обрезки пробелов |
| `channel` | строка | только `email`, `form`, `chat` |
| `client_id` | строка | 1-64 символа, нужен для лимита запросов |

**Ответ 200**

| Поле | Тип | Значения |
|---|---|---|
| `category` | строка | `billing`, `support`, `complaint`, `other` |
| `draft_reply` | строка | 1-6 предложений |
| `confidence` | строка | `high`, `medium`, `low` |
| `escalate` | bool | нужен ли человек |

**Ошибки:** 422 (не прошла валидация), 429 (превышен лимит, заголовок `Retry-After`). При сбое модели ответ всё равно 200, но `escalate=true` и шаблонный текст «передано оператору» (так требует задание: клиент не остаётся без ответа).

## 3. Стек и почему

| Выбор | Почему |
|---|---|
| Python 3.12 + **FastAPI** | валидация контракта (pydantic) даёт 422 из коробки; автодокументация `/docs` годится для демо-видео; Survey Platform LP уже на FastAPI, значит перенос в LP без смены фреймворка |
| **SQLAlchemy 2** + `DATABASE_URL` | сейчас `sqlite:///...`, на LP подставим строку PostgreSQL, код не трогаем |
| Claude через ProxyAPI, SDK `anthropic` | как в Кейсе 2: `PROXY_API_KEY`, `PROXY_API_BASE_URL`, `CLAUDE_MODEL=claude-sonnet-5-5` |
| pytest | тесты без живой модели (модель подменяем заглушкой) + один отдельный живой прогон |
| Docker, порт 8000 | шаг 5; не 5000 (занят AirPlay) |

Язык и фреймворк в тексте ДЗ не зафиксированы, это моё предложение.

## 4. Структура папки

```
ai_triage_service/
  app/
    main.py          - FastAPI: маршруты, обработка ошибок (тонкий слой)
    schemas.py       - модели запроса и ответа (контракт)
    triage.py        - ядро: собрать промпт, вызвать модель, проверить JSON, решить escalate
    llm.py           - клиент Claude (единственное место, где знают про ProxyAPI)
    limiter.py       - лимит N запросов в минуту на client_id (счётчик в БД)
    store.py         - таблица tickets, запись и чтение
    config.py        - настройки из env
  config/
    triage.yaml      - категории, правила эскалации, шаблон «передано оператору»
    prompt.md        - системный промпт
    knowledge.md     - справка о компании (на ДЗ: вымышленная компания)
  tests/
  scripts/           - check_service.py (шаг 5), demo_requests (шаг 4)
  Dockerfile, requirements.txt, .env.example, README.md
  submission_text.md   - вне git и вне zip
```

## 5. Как это идёт по шагам запроса

1. `schemas.py` проверяет входящий JSON. Не прошёл - 422, в базу не пишем.
2. `limiter.py` смотрит, сколько запросов от этого `client_id` было за последнюю минуту. Лишний - 429.
3. `triage.py` собирает промпт: `prompt.md` + `knowledge.md` + текст обращения. Температура 0.2, ответ модели строго JSON.
4. `llm.py` вызывает Claude. Таймаут, одна повторная попытка.
5. `triage.py` проверяет, что JSON пришёл в нужной форме и значения из допустимых списков. Не пришёл - считаем сбоем.
6. Правила эскалации (из `triage.yaml`): `escalate=true`, если `category=complaint`, или `confidence=low`, или сбой модели. Это решает код, а не модель: управляемо и проверяемо тестом.
7. `store.py` пишет строку в `tickets`: время, `client_id`, `channel`, текст, результат, поле `error`.
8. Клиенту уходит ответ.

## 6. База: таблица `tickets`

| Поле | Содержание |
|---|---|
| `id` | автономер |
| `created_at` | время UTC |
| `client_id`, `channel`, `text` | вход |
| `category`, `draft_reply`, `confidence`, `escalate` | результат |
| `error` | текст сбоя модели или пусто |
| `model`, `latency_ms` | для отчёта и разбора качества |

Лимит считается запросом в эту же таблицу (число строк `client_id` за последнюю минуту), отдельное хранилище не нужно. Недостаток: в лимит попадают и неудачные вызовы, поэтому в `tickets` пишем **все** принятые обращения, включая сбои. Это сознательное решение.

## 7. Секреты и данные

- Ключ только в `.env` (вписывает Андрей), в `.gitignore`. В чат и в репозиторий не попадает.
- Тестовые обращения только вымышленные: тексты уходят во внешнюю модель. Пункт для «Рисков» в защите.
- Тексты клиентов в логах не печатаем, только id тикета и длину.

## 8. Заделы под перенос в LP (без переписывания)

| Что | Как сделано сейчас | Что поменяется при переносе |
|---|---|---|
| База | `DATABASE_URL` | подставим строку PostgreSQL кластера Timeweb |
| Тексты и правила | `config/*.md`, `triage.yaml` | заменим файлы на тексты LP, код не трогаем |
| Домены сайта | `CORS_ORIGINS` из env | впишем `legal-privacy.ru` |
| Лимит | по `client_id`, не по IP | на сайте `client_id` = анонимная cookie (по IP на Timeweb нельзя: он не передаётся) |
| Бюджет | счётчик в БД | добавим дневной лимит токенов (в ДЗ не обязателен) |

Чего в ДЗ сознательно **нет** (чтобы не раздувать): истории диалога, виджета на сайте, согласия на ПДн, Telegram-эскалации. Это отдельный этап после зачёта, согласуется с Татьяной.

## 9. Критерии «готово» (проверяемые)

| № | Критерий | Чем проверяем |
|---|---|---|
| 1 | Корректный запрос возвращает 200 и все 4 поля с допустимыми значениями | pytest + живой прогон |
| 2 | Пустой `text`, текст >2000, неверный `channel`, нет `client_id` - 422, строка в БД не создаётся | pytest |
| 3 | Каждое принятое обращение есть в `tickets` | pytest + демо-видео |
| 4 | N+1-й запрос за минуту от одного `client_id` - 429 с `Retry-After`; другой `client_id` не затронут | pytest |
| 5 | Сбой модели (таймаут, ошибка, мусор вместо JSON): 200, `escalate=true`, шаблонный текст, `error` заполнено | pytest с заглушкой |
| 6 | `complaint` и `low` всегда дают `escalate=true` | pytest |
| 7 | Ключа нет в git, в логах и в zip; без ключа сервис падает с понятным сообщением | проверка вручную + тест |
| 8 | 8-10 вымышленных обращений: категория совпадает с ожидаемой не менее чем в 80% (цель, фактическое число честно в отчёт) | живой прогон, таблица в отчёте |
| 9 | Запуск по README за 5-10 минут на чистой папке, в том числе через Docker | проверка в пустой директории |
| 10 | Все 6 артефактов сдачи подготовлены | шаги 6-7 |
